# DevOps Professional — 6 Days × 3 h 30 m

A complete, self-contained delivery kit for the **DevOps Professional** course: detailed
theory notes, diagrams and workflows for all nine modules, plus **20 hands-on labs** that
chain together into one end-to-end DevOps platform.

Everything runs on **Ubuntu 24.04 LTS on localhost**, or on a **free** hosted tier
(GitHub Free + GitHub Actions + GitHub Container Registry). No cloud account, no credit
card, no paid licences are required at any point.

---

## Delivered to UniCredit

This edition is written for a **banking audience** and the decks carry
`NOBLEPROG · DEVOPS PROFESSIONAL · UNICREDIT` on the cover. The sample application is a payments
service, the examples use bank processes, and every module cross-references
**[Appendix A — DevOps in a Regulated Bank](docs/theory/appendix-a-devops-in-a-regulated-bank.md)**:
segregation of duties without a CAB meeting, audit evidence generated by the pipeline,
PCI-DSS and EU DORA in practice, production data in lower environments, change freezes, and
how any of this meets a mainframe.

> **Re-using this for another client.** The written material deliberately names no bank in its
> body text — only the deck covers carry the client name, from one variable. To re-brand:
> change `client='UniCredit'` in `_build/deckkit.py` (`s_title`) and re-run `python build.py`.

## The one thread that runs through every lab

Every lab operates on the same application, **PayTrack API** — a small Flask + PostgreSQL
card-authorisation service. Money is held as integer minor units, a full card number is
refused at the API edge (PCI scope you design out rather than secure later), and no customer
identifier reaches the logs. You will carry it from a bare directory on
day 1 to a monitored, secured, GitOps-deployed workload on day 6.

```
Day 1   bare files ──► git repo ──► GitHub
Day 2                              ──► CI pipeline (GitHub Actions + Jenkins)
Day 3                                                ──► Docker image ──► Compose stack
Day 4                                                                  ──► Kubernetes
Day 5   Terraform provisions the cluster & namespaces │ Ansible configures the nodes
                                                       ──► CD pipeline ──► blue/green
Day 6                                                  ──► scanned, signed, monitored
```

**Nothing is thrown away.** Lab *N* consumes what lab *N‑1* produced. If a delegate falls
behind, each lab README has a `RECOVER` section with a one-command fast-forward.

## Before day 1 — delegate prerequisites

| Requirement | Detail |
|---|---|
| **Machine** | Ubuntu 24.04 LTS, **4 vCPU / 8 GB RAM / 40 GB free disk** (bare metal, VM, or WSL2). 8 GB is a hard floor: day 4 runs a Kubernetes cluster and day 6 adds Prometheus + Grafana. |
| **Access** | `sudo` on that machine, and outbound HTTPS on 443. |
| **Accounts** | A free **GitHub** account. Nothing else. |
| **Setup** | One command: `sudo ./scripts/install-ubuntu24.sh` — installs and verifies the whole toolchain, idempotently. Re-check any day with `--verify` |
| **Skills** | Comfortable in a Linux shell (`cd`, `ls`, `cat`, `vim`/`nano`, `systemctl`); aware of what an HTTP request and a TCP port are; has seen source code before. |

> **No Ubuntu machine?** Use [GitHub Codespaces](https://github.com/features/codespaces)
> (60 free core-hours/month on the free tier) or a local VM in
> [VirtualBox](https://www.virtualbox.org/) / [Multipass](https://multipass.run/)
> (`multipass launch 24.04 --name devops --cpus 4 --memory 8G --disk 40G`).
> Lab 00 covers both paths.

## How to use this kit

> 📇 **Keep [`reference/access-card.md`](reference/access-card.md) open all week** — it has
> every URL, port, password and start/stop command in one page, including the port-8080
> conflict that catches most rooms on day 4.

**Delegates** — work straight down `labs/lab-00…` → `lab-19`. Read the matching theory
module before each block; the trainer will lecture it, and the notes go deeper than the
slides do.

**Trainers** — follow `docs/run-sheet.md`. Each lab README ends with an
**Instructor notes** block: expected duration, the three failures that actually happen in
the room, and the debrief question to close the exercise on.

**Self-study** — the labs are written to be completed unattended. Every command is given
in full with an explanation of what it does and what output proves it worked.

## Conventions used in every lab README

| Marker | Meaning |
|---|---|
| `$` prefix omitted | Every fenced `bash` block is meant to be run as-is in your shell |

| ✅ **Checkpoint** | Run this to prove the step worked before moving on |
| ⚠️ **Gotcha** | A failure mode we know you will hit |
